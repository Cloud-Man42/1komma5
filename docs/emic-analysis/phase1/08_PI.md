# Pi Display — LKG & Connection States

**Status:** Implemented (frontend)  
**Related:** [`docs/PI_KIOSK.md`](../../PI_KIOSK.md)

---

## Overview

Raspberry Pi kiosk displays use authenticated `GET /api/v1/display/overview/{slug}`. Phase 1 adds client-side **Last Known Good (LKG)** caching and explicit connection states so the UI remains usable during brief network failures.

Baseline Pi latency: **UNMEASURED** (requires display device token — [`01_BASELINE.md`](01_BASELINE.md)).

---

## localStorage LKG

**File:** [`frontend/src/lib/piDashboardStorage.ts`](../../../frontend/src/lib/piDashboardStorage.ts)

| Function | Behaviour |
|----------|-----------|
| `loadPiLastKnownGood(slug)` | Read `emic:pi:lkg:{slug}` from localStorage |
| `savePiLastKnownGood(slug, overview)` | Persist successful fetch |
| `formatLastUpdated(overview)` | Format `generated_at` as `sv-SE` time (HH:mm:ss) |

Storage key per site slug. Quota errors silently ignored.

---

## Connection states

**Type:** `PiConnectionState` — `CONNECTED` | `STALE` | `RECONNECTING` | `OFFLINE`

**Logic:** `derivePiConnectionState(overview, fetchFailed)`

| Condition | State |
|-----------|-------|
| No overview, fetch failed | `OFFLINE` |
| No overview, fetch pending | `RECONNECTING` |
| Fetch failed, LKG age ≤ 900 s | `STALE` |
| Fetch failed, LKG age > 900 s | `OFFLINE` |
| `freshness.stale` true | `STALE` |
| `data_age_seconds` > 120 | `STALE` |
| Otherwise | `CONNECTED` |

## Data hook

**File:** [`frontend/src/lib/usePiDashboardData.ts`](../../../frontend/src/lib/usePiDashboardData.ts)

| Property | Default |
|----------|---------|
| Poll interval | **4 s** (`POLL_MS`) |
| Backoff on error | Exponential up to **30 s** |
| Initial state | LKG from localStorage if present |

On success: update data, save LKG, reset backoff, set `lastUpdated`.  
On failure: show LKG with `STALE`/`OFFLINE`, increase backoff.

Returns: `{ data, connection, error, lastUpdated, reload }`.
